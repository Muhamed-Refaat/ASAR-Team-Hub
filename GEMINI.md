# Repository rules

## Synchronization

- Keep production and local interfaces identical. Edit shared `web/` sources and run `python tools/build_dashboard.py` to regenerate `Index.html`, `local_test_dashboard.html`, and `Code.gs`.
- Use `python sync_local_db.py` to import the workbook and regenerate CSVs plus the embedded local fallback. Do not hand-edit CSVs without updating the workbook.
- Schema changes must be reflected in the workbook, CSVs, local adapter, and Apps Script controller. Preserve nonempty source cells.

## UI and data

- Use React 18, lightweight pinned CDNs, Lucide icons and ApexCharts. Shared CSS uses consistent spacing and accessible light/dark design tokens, Plus Jakarta Sans with an Arabic font fallback, visible keyboard focus, and responsive layouts.
- Missing ratings and qualifications stay missing. Display only recorded profile, education, task, assessment and completion data in the interface and CVs.
- CVs use shared web/cv.js layouts for Word and PDF: a professional A4 header, two-column content and toolkit sidebar. Omit placeholders, empty sections, internal ratings and participation counters. Include actual team appointments, completed or active project work, and approved completed learning; never present pending learning or backlog assignments as experience.
- Keep event cards compact: group metadata and progress, put named icon tools beside status, keep task status/evidence shortcuts and primary actions side by side where space allows, and offer Read more for long descriptions. Preserve full text, permissions, status/undo/review controls and visible upcoming meetings; keep touch targets usable.
- Event management belongs in Tasks, Meetings, Learning, and Skills; Exams is inactive. Learning courses cannot be archived. Meeting attendance requires the admin-controlled Logging Enabled flag. Required skills follow per-member sheet definitions and SkillRequirements overrides.
- Team Intelligence uses the searchable member directory and selected profile, with the member's progress graph before the radar matrix. Show Technology, Skills, Knowledge, Abilities and Personality as text-only lists directly below the overview using recorded data; no counters, ratings or progress bars in these lists, and no team event-counter section. Completion logs and Activity follow Team Intelligence in navigation.
- Event management belongs in the dedicated event tabs. Tasks have a separate management action. Completion records belong in Completion logs; Activity displays user actions, reviews, evidence, management changes and authenticated errors.
- Only explicitly listed Admins can create/edit/archive/reopen events, review submissions or edit distribution. A leadership role alone is not authorization. Courses and attendance use Uncompleted/Pending/Completed; pending records never count as completed. Evidence is optional for both courses and meetings; supplied PDF/PNG/JPEG files up to 10 MB are validated and stored in Drive with sheet metadata. Preserve all attempts and review history. Members can withdraw pending or undo approved records; stale reviews must fail. Admins can explicitly reject submissions: restore Uncompleted, retain the attempt/reviewer/optional feedback, audit the rejection and allow resubmission. Return for changes remains available with required feedback. Task completion follows board Status only; no completion form or personal task completion writes. Skills retain direct completion.
- New event creation closes the form immediately after local validation and uses web/sync.js for background saves. Keep saving/failed drafts separate from confirmed progress, retain retryable fields, reuse stable IDs, serialize writes and refreshes, and never close a newer dialog when an earlier save finishes. Restore unconfirmed drafts from session storage when available without automatically resubmitting them.
- Telegram announcements require a saved course (including imported courses), or a recorded Task/Meet creation, a member-visible preview, and explicit admin confirmation. Bind the server's short-lived preview receipt to the authenticated admin, exact message and destination. Keep bot credentials in Script Properties. Telegram announcements use emoji headings and safe bold/italic entities with UTF-16 offsets; previews render the same entity spans as the delivered message. Preserve plain-text legacy deliveries and never interpret sheet text as HTML. Keep TELEGRAM_CHAT_ID on the verified test group -5382073850 until the user authorizes switching back to the production group -1004488318175. Deduplicate announcements per event and destination; never reroute prior approvals. Use the existing Activity sheet as the durable delivery queue; no network calls under the script lock or in event-save requests. Retry explicit rate-limit/server failures with backoff; ambiguous deliveries require a fresh preview and manual retry. Local previews never post messages. Setup instructions are in docs/telegram-setup.md.
- All mutations use immediate local feedback and background saving through web/actions.js and the shared serial queue. Keep the confirmed snapshot separate, show unconfirmed writes only through a compact indicator beside Refresh, keep failure recovery available on click without a page-level action log or saving toasts, retain retryable failures, roll back only unconfirmed changes and preserve newer queued choices. Stable commandId values make server retries idempotent; newId remains the source/submission identity. Backend replies must never close newer forms. Skip superseded task moves that have not started; retain ordering for submissions and reviews. Reuse request-scoped sheet snapshots and return the validated persisted result instead of reading the workbook twice. CV exports always use confirmed member/data snapshots. Local validation, active-user authorization and server checks remain mandatory. Refresh quietly on returning to the app.
- Task assignees and admins add evidence URLs directly from task cards, with the URL as the only entry field. Do not ask for purpose or notes. Retain historical extra metadata, author attribution and soft removals in Task Evidence Links; preserve the board status and never trust a supplied author. Learning and meeting evidence fields remain available. Activity shows user actions and authenticated failures with member/category filters, bounded rendering and expandable debug details; never audit uploads or full request payloads. Meeting attendance controls use a properly sized switch, settings stay admin-only, and safe meeting URLs have a Join meeting hyperlink.
- Team Active defaults to true when missing. Admins remove members by setting Active to FALSE and disabling their memberships, preserving rows, identities, completions and audit history. Inactive members cannot authenticate or receive assignments and do not count toward current event denominators. Protect the overall Team Leader, sole subteam leaders and last enabled admin. New members apply through the linked Google Form; forms/TeamApplications.gs is installed separately in the Form's project and preserves role/hierarchy/removal fields when updating verified profiles. Never grant Admins permissions through a form submission.
- Show Admin badges from the enabled Admins list alongside team roles in hierarchy, member directory/profile, dashboard and account header. Admin review is available directly from pending event cards and Completion logs as well as each event tab's queue. Pending-review filters and navigation counts use current pending attempts across all members for admins. Explicit admins can review their own attendance; stale or withdrawn attempts are never actionable.
- The dashboard is a landing page with real progress visuals, scroll reveals and reduced-motion support. Keep styling, lookups and the delivery copy synchronized using tools/style_workbook.py when changing workbook data/schema.
- The production backend must authorize from `Session.getActiveUser().getEmail()`. Never trust payload identities, substitute the effective user, or default to the first team member.
- Keep exactly one overall Team Leader. Subteams have one or more leaders. TeamMemberships stores one Leader/Member/Support role per member per subteam, and members can belong to several subteams. Derive compatibility Team Role/Department/Reports To summaries from these relationships. Leadership grants no Admins permissions. Disable removed settings rows rather than deleting or reordering them.
- Skills shows required project skills only, with Update result and Reset skill for the signed-in member. Retain all attempts and original ratings; only the latest completed assessment per event affects the skill matrix. Prior standalone assessments remain archived history. Completion/request controls for courses, meetings and skills stay on event cards. Tasks use drag/drop or the status dropdown.
- References is a shared searchable link library. All active team members can add a title, safe http/https URL and optional description; only enabled admins can delete links. Authenticate attribution on the server, preserve deleted rows and Activity, and use the shared immediate-update queue.
- Only enabled admins can delete tasks, meetings and courses after confirmation. Set Deleted TRUE on source and linked Log rows; preserve rows, completion attempts, evidence and audit history. Exclude deleted events from assignments, progress, CVs, reviews and notifications. Cancel queued announcements and recheck source deletion in the worker before claiming a delivery.
- Event creation uses only essential type-specific fields in HubModel.EVENT_FORM_FIELDS/EVENT_COLUMNS. Preserve legacy source cells; hide obsolete columns in the workbook and avoid overwriting them during edits. Extra course/meeting details stay in optional settings.
- Legacy aliases are explicit, never guessed. Retain historical invited/completed totals when names cannot yet be linked to current members.

## Verification

Run the model/backend tests, the real local browser workflow, and the data/CV audit before declaring changes complete. Browser evidence must cover responsive layouts, text contrast, permission controls, completion and matrix updates, hierarchy and CV exports. Follow the deployment steps in README when publishing; a local mock is not proof of a hosted deployment.
